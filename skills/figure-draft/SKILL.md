# Figure-draft

把科学论点转成读者能准确理解、作者能继续编辑的图。科研配图相关请求可自动选用本入口，也可显式调用 `$figure-draft`；按当前阶段选择模块，完成后在同一流程交付。默认使用中文沟通，图内语言服从稿件。

结合当前请求与已有画图上下文识别意图，例如“这张图该讲什么”“参考 Acta 的排版”“第二稿的箭头再调一下”。自动选用只决定读取哪些指导；用户说“先讨论/给建议”时完成对应讨论或审查，实际生图、改图和应用操作按请求范围推进。仅提到论文中的 Figure、解释他人结果或讨论 Skill 设置，不因此开始绘图。

## 1. 识别入口

先从最新要求识别本轮操作，再结合内容和图源确定 `kind`（示意、结构、定量或混合）与 `stage`。只审图、改字、写图注、组版或导出，直接进入对应操作。有 `figure-state.yaml` 时先读它并核对所指文件；首次只有散乱记录时提取相关决定即可。

执行方式继承实际图源：Affinity 原生文件用 Affinity；SVG/参数脚本保留原图源；定量标记回到数据绘图后端；示意位图的生成/编辑用 imagegen。文件扩展名不决定图的身份：PNG 中的数据曲线与显微影像仍按真实数据/影像处理。混合图按面板分流，只统一组版。

| 用户当前需要 | stage | 本次读取 | 本阶段应交付 |
|---|---|---|---|
| 想清楚图讲什么、核对机制、讨论哪些内容必要 | `brief` | [论点与沟通](references/brief.md) | 图的核心句、内容与证据映射、必要选择 |
| 已有内容，讨论构图、比例、面板与排版 | `layout` | [布局](references/layout.md)；类型未定时读[类型索引](references/taxonomy.md) | 可比较的线框方案及推荐 |
| 指定期刊找参考，或给了参考图 | `reference` | [参考调研](references/reference-research.md) | 逐图可追溯参考卡与视觉规则 |
| 生成示意图初稿、探索三种画风 | `explore` | [生图与迭代](references/image-generation.md)、[视觉验收](references/review.md) | 同内容的三个独立候选及逐张自审 |
| 从数据新画/重画，修改轴、统计、误差线或数据标记 | `plot` | [数据绘图](references/data-figures.md) | 保留数据和计算依据的图源、渲染与数据验收 |
| 已选定图，精修一处或恢复某版画风 | `refine` | 按图源选一个：示意位图读[生图](references/image-generation.md)，原生文件读[Affinity](references/affinity.md)，SVG/脚本读[矢量图源](references/vector-editing.md)，定量内容读[数据绘图](references/data-figures.md)；可见修改再读[验收](references/review.md) | 定向修改及相关回归 |
| 重建示意形状与独立文字 | `vector` | 目标 `.af` 读[Affinity 重建](references/affinity.md)；目标 SVG/脚本读[矢量图源](references/vector-editing.md)；再读[验收](references/review.md) | 指定格式的可编辑对象 |
| 只评价现图、独立复核、查错 | `review` | [视觉验收](references/review.md) | 有位置与证据的问题清单；按授权决定是否修图 |
| 导出、固定面板组版、配图注、整合正文、投稿检查 | `deliver` | [交付与整合](references/delivery.md)的对应小节 | 指定文件和与当前图一致的图注/正文 |

先读匹配的一个主模块；跨阶段任务进入下一阶段时再加载。执行模块在需要具体规范/工具时才读取对应能力库的入口或章节，由当前 Agent 完成调用，不要求用户另行调用 Skills。已读且仍适用的文件直接复用；记录读取范围，只有来源变化、上下文缺失或工具重连时补读。不要预读全部 references、全部语料、Affinity SDK 或所有能力库。已完成阶段只在相应决定失效时回退。

## 2. 贯穿流程的约定

- 用一句话确定图的科学职责，并识别它与相邻图、正文、图注的分工。每个箭头、空间关系和材料外观都可能形成科学主张。
- 延续用户已确认的内容、布局及风格。用户给出现成图要求复刻/局部修改，即可进入相应阶段；不要重新要求完整立项或强制再生成三稿。
- 用户要求先讨论或先选稿时，完成可判断的方案/候选后等其选择。其他情况下只问会实质改变科学含义、构图或交付物的缺失信息，继续独立工作。
- 将 `content_master`、`style_reference`、`geometry_reference` 和 `text_master` 分开指定。较早画风参考只控制指定的风格属性。
- 示意形状和文字独立制作。Affinity 示意部分以有意义的形状、Bézier 曲线、原生填充及真实文字对象构成；真实影像和冻结数据面板保留原始身份。对象可编辑性与外观相似度分别验收。
- 每张生成图、每次可见修订都执行“查看当前输出 → 核对改动 → 检查整图回归”。先纠正科学关系，再处理几何和文字，最后打磨质感。
- 图内保留识别实体、关系、方向和状态所需的短标签。方法、证据边界、线型解释和来源放在恰当的图注或正文位置，按读者需要保留。
- 以观察到的事实报告进度。原生文件存在、导出无位图、模型说通过、作者已认可、期刊允许使用是不同状态。
- 保存版本和原始证据。科学或布局改变后同步相关图注，整合正文仅在请求覆盖时进行。

## 3. 状态与接续

长任务按[状态模板](references/state-and-handoff.md)维护简短的 `figure-state.yaml`、`labels.json` 和修订/验收记录。小改动可把同样的信息写在一条记录里。下一位执行者应能知道当前主文件、已定事项、本轮改变、待核实事实与下一步。

新示意方向通常按 `brief → layout/reference → explore → refine → vector → deliver` 推进；已定内容可直接绘制。数据图通常为 `plot → review → deliver`。`review` 是每轮的回路，也可以单独进入。示意类型选择看[类型索引](references/taxonomy.md)，按类别再读一组设计卡；定量图型由数据模块选择。图形摘要是交付用途，仍需选择其内部的科学叙事类型。

## 4. 统一入口与能力库

从本 Skill 进入时，`workflow_owner: figure-draft` 贯穿各阶段。下列 Skills 是按需使用的能力库：负责各自技术规范和工具，不接管整段用户流程。继承主文件、已定内容/风格、执行方式、本次改动及输出要求；完成后返回当前阶段，不再次路由上游。职责不清时再读[分工与交接](references/skill-handoff.md)。直接调用其他 Skill 的独立任务仍可保留原入口。

| 实际任务 | 按需使用 |
|---|---|
| 绘制/改动定量面板 | 本 Skill 的[数据模块](references/data-figures.md)按需使用 `nature-figure` 的后端和数据验收规范 |
| 只查期刊要求、图注或定量审查 | `nature-figure` 的对应参考段落；不启动绘图后端 |
| 已定拓扑的框图、流程图、结构图，或已有 SVG/参数图源 | `paper-figure` 的所选图型规范/模板；继承已定配色和尺寸，不重启三稿探索 |
| 正文论证或实质改写 | `nature-writing`，只加载相关章节；纯配色/矢量化不读写作全套 |
| 已有正式审稿意见与回复 | `nature-response`；普通自审用本 Skill 的 review，不创建虚构审稿包 |
| 标签、图注、交付说明措辞 | `anti-defensive-writing`；有纠正或弃稿时再用 `no-negative-echo`，以接受后的内容生成对外表述 |
| 实际位图生成或编辑 | 可用的 `imagegen` 能力，内置工具为默认；工具参数以当次 schema 为准 |
| 原生 Affinity 操作 | `affinity`，先查现有连接与能力，再按需要读矢量、文字和导出文档 |
| 机制事实或参考文献不足 | 学术检索/本地 Zotero 能力，核对原文及相应图/表 |

首次准备投稿候选、实际投稿前或用途/目标期刊改变影响适用规则时，读取[期刊与来源](references/policy-and-provenance.md)。其他局部修改/格式转换复用有效记录。保存真实 AI 使用记录；矢量重建不改变创作来源。

通用 SDK、图型模板和 Python/R 工具由对应能力库维护；阶段编排、示意设计与逐轮接续集中在本 Skill。首次连接工具或辅助技能缺失时读[工具与技能接入](references/integrations.md)。仅借用参考段落/工具时执行相应部分。已确认的数据面板作为固定资产保留，任何数据标记改动回到原数据后端。

独立复核按当前可用且获授权的执行者安排。外部模型按当前聊天授权和相应工具规则使用；安装了 `gemini-bridge` 且用户选择该路线时，再读取其操作规则。主 Agent 核验实际看图范围与每条意见后决定采纳。

## 5. 完成判断

以当前请求的阶段目标为准。交付前至少看过实际产物，并说明还影响使用的实质缺口。纯矢量成品可运行 [audit_vector.py](scripts/audit_vector.py) 检查 SVG/PDF 结构；自动检查不能证明曲线质量、遮挡、科学准确性或原生编辑行为。完整验收规则见 review 与 delivery。

需要了解各阶段怎样衔接时，读[材料界面图示例](references/worked-example.md)。
