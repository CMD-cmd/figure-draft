# Figure-draft

把科学论点转成读者能准确理解、作者能继续编辑的图。通过所用 Agent 的技能机制加载，或在请求中点名 Figure-draft 并读取本文件；按当前阶段加载所需模块，完成后在同一流程内交付。默认使用中文沟通，图内语言服从稿件。

调用语法、自动发现和工具接入遵循当前 Agent 的平台约定。核心流程使用本文件与 `references/`；`agents/openai.yaml` 是可选的平台适配配置。生成、编辑、渲染与独立复核按实际可用工具执行。

结合当前请求与已有画图上下文识别意图，例如“这张图该讲什么”“参考 Acta 的排版”“第二稿的箭头再调一下”。自动选用仅决定读取哪些阶段指导：用户要求“先讨论/给建议”时只完成对应讨论或审查，实际生图、改图和应用操作严格按请求范围推进。仅提到论文中的 Figure、解释他人结果或讨论 Skill 设置时，不因此开始绘图。

## 1. 识别入口

先从最新要求识别本轮操作，再结合内容和图源确定 `kind`（示意、结构、定量或混合）与 `stage`。只审图、改字、写图注、组版或导出时，直接进入对应操作。有 `figure-state.yaml` 时先读它并核对所指文件；首次只有散乱记录时提取相关决定即可。

执行方式继承实际图源：Affinity 原生文件（`.af`）用 Affinity；SVG 或参数脚本保留原图源；定量标记改动回到数据绘图后端；示意位图的生成与编辑用 `imagegen`。文件扩展名不决定图的身份：PNG 中的数据曲线与显微影像仍按真实数据/影像处理，不用生图模型重绘。混合图按面板分流处理，最后统一组版。

| 用户当前需要 | stage | 本次读取 | 本阶段应交付 |
|---|---|---|---|
| 想清楚图讲什么、核对机制、讨论哪些内容必要 | `brief` | [论点与沟通](references/brief.md) | 图的核心句、内容与证据映射、待确认的关键选择 |
| 已有内容，讨论构图、比例、面板与排版 | `layout` | [布局](references/layout.md)；类型未定时读[类型索引](references/taxonomy.md) | 可比较的线框方案及推荐理由 |
| 指定期刊找参考，或给了参考图 | `reference` | [参考调研](references/reference-research.md) | 逐图可追溯参考卡与可执行的视觉规则 |
| 生成示意图初稿、探索三种画风 | `explore` | [生图与迭代](references/image-generation.md)、[视觉验收](references/review.md) | 同内容的三个独立候选及逐张自审 |
| 从数据新画/重画，修改轴、统计、误差线或数据标记 | `plot` | [数据绘图](references/data-figures.md) | 保留数据和计算依据的图源、渲染结果与数据验收 |
| 已选定图稿，精修局部或恢复某版画风 | `refine` | 按图源选一个：示意位图读[生图](references/image-generation.md)，原生文件读[Affinity](references/affinity.md)，SVG/脚本读[矢量图源](references/vector-editing.md)，定量内容读[数据绘图](references/data-figures.md)；可见修改再读[验收](references/review.md) | 定向修改结果与回归检查 |
| 重建示意形状与独立文字 | `vector` | 目标 `.af` 读[Affinity 重建](references/affinity.md)；目标 SVG/脚本读[矢量图源](references/vector-editing.md)；再读[验收](references/review.md) | 指定格式的可编辑对象及编辑性验证 |
| 只评价现图、独立复核、查错 | `review` | [视觉验收](references/review.md) | 标明位置与证据的问题清单；按授权决定是否修图 |
| 导出、固定面板组版、配图注、整合正文、投稿检查 | `deliver` | [交付与整合](references/delivery.md)的对应小节 | 指定格式文件及与当前图一致的图注/正文 |

先读匹配的一个主模块；跨阶段任务进入下一阶段时再按需加载。执行模块在需要具体规范或工具时才读取对应能力库的入口或章节，由当前 Agent 直接完成调用，不要求用户另行调用其他 Skills。已读且仍适用的文件直接复用；记录读取范围，只有来源变化、上下文缺失或工具重连时补读。不要预读全部 `references`、全部语料、Affinity SDK 或所有能力库。已完成阶段只在相应决定失效时回退。

## 2. 贯穿流程的约定

- 用一句话确定图的科学职责，并明确它与相邻图、正文、图注的分工。每个箭头、空间关系和材料外观都可能构成科学主张。
- 延续用户已确认的内容、布局及风格。用户给出现成图要求复刻或局部修改时，直接进入相应阶段；不要重新要求完整立项或强制再生成三稿。
- 用户要求先讨论或先选稿时，完成可判断的方案或候选后等待其选择。其他情况下只追问会实质改变科学含义、构图或交付物的缺失信息，其余步骤继续独立完成。
- 将 `content_master`（内容主稿）、`style_reference`（风格参考）、`geometry_reference`（几何参考）和 `text_master`（文字台账）分开指定。借用早期画风时，参考图只控制指定的风格属性，不覆盖当前内容与几何。
- 示意形状和文字独立制作。Affinity 示意部分以有意义的形状、Bézier 曲线、原生填充及真实文字对象构成；真实影像和冻结数据面板保留原始身份。对象可编辑性与外观相似度分别验收。
- 每张生成图、每次可见修订都执行“查看当前输出 → 核对本轮改动 → 检查整图回归”。先纠正科学关系，再处理几何和文字，最后打磨质感。
- 图内保留识别实体、关系、方向和状态所需的短标签。方法、证据边界、线型解释和来源放在恰当的图注或正文位置。
- 按实际验证到的事实报告进度：原生文件存在、导出不含位图、视觉模型判通过、作者已认可、符合期刊政策是不同状态，不可混同。
- 保存版本和原始证据。科学内容或布局改变后同步更新相关图注；整合回正文仅在请求包含该步骤时进行。

## 3. 状态与接续

长任务按[状态模板](references/state-and-handoff.md)维护简短的 `figure-state.yaml`、`labels.json` 和修订/验收记录；小改动可把同样信息写在单条记录里。下一位执行者应能直接获知当前主文件、已定事项、本轮改动、待核实事实与下一步。

新示意方向通常按 `brief → layout/reference → explore → refine → vector → deliver` 推进；已定内容可直接绘制。数据图通常按 `plot → review → deliver` 推进。`review` 既是每轮修改的内嵌回路，也可单独进入。示意类型选择看[类型索引](references/taxonomy.md)，按类别再读对应的一组设计卡；定量图型由数据模块选择。图形摘要属于交付用途，仍需选择其内部的科学叙事类型。

## 4. 统一入口与能力库

从本 Skill 进入时，`workflow_owner: figure-draft` 贯穿各阶段。下列 Skills 是按需调用的能力库：只负责各自技术规范和工具，不接管整段用户流程。调用时继承主文件、已定内容/风格、执行方式、本次改动及输出要求；完成后返回当前阶段，不重新路由回上游。职责边界不清时读[分工与交接](references/skill-handoff.md)。用户直接调用其他 Skill 的独立任务仍保留原入口。

| 实际任务 | 按需使用 |
|---|---|
| 绘制/改动定量面板 | 本 Skill 的[数据模块](references/data-figures.md)按需使用 `nature-figure` 的后端和数据验收规范 |
| 只查期刊要求、图注或定量审查 | `nature-figure` 的对应参考段落；不启动绘图后端 |
| 已定拓扑的框图、流程图、结构图，或已有 SVG/参数图源 | `paper-figure` 的所选图型规范/模板；继承已定配色和尺寸，不重启三稿探索 |
| 正文论证或实质改写 | `nature-writing`，只加载相关章节；纯配色/矢量化不读写作全套 |
| 已有正式审稿意见与回复 | `nature-response`；普通自审用本 Skill 的 `review`，不创建虚构审稿包 |
| 标签、图注、交付说明措辞 | `anti-defensive-writing`；有纠正或弃稿时再用 `no-negative-echo`，以接受后的正向内容生成对外表述 |
| 实际位图生成或编辑 | 可用的 `imagegen` 能力，默认使用内置工具；参数以当次工具 schema 为准 |
| 原生 Affinity 操作 | `affinity`，先查现有连接与能力，再按需读矢量、文字和导出文档 |
| 机制事实或参考文献不足 | 学术检索/本地 Zotero 能力，核对原文及相应图/表 |

首次准备投稿候选、实际投稿前或用途/目标期刊改变影响适用规则时，读取[期刊与来源](references/policy-and-provenance.md)。其他局部修改或格式转换复用有效记录。保存真实 AI 使用记录；矢量重建不改变创作来源。

通用 SDK、图型模板和 Python/R 工具由对应能力库维护；阶段编排、示意设计与逐轮接续集中在本 Skill。首次连接工具或辅助技能缺失时读[工具与技能接入](references/integrations.md)。仅借用参考段落或工具时只执行相应部分。已确认的数据面板作为固定资产保留，任何数据标记改动均回到原数据后端。

独立复核按当前可用且获授权的执行者安排。外部模型按当前聊天授权和相应工具规则使用；安装了 `gemini-bridge` 且用户选择该路线时，再读取其操作规则。主 Agent 核验实际看图范围与每条意见后决定是否采纳。

## 5. 完成判断

以当前请求的阶段目标为准。交付前至少实际查看过当前产物，并说明仍影响使用的实质缺口。纯矢量成品可运行 [audit_vector.py](scripts/audit_vector.py) 检查 SVG/PDF 结构；自动结构检查不能证明曲线质量、无遮挡碰撞、科学准确性或原生软件中的编辑行为。完整验收规则见 [review](references/review.md) 与 [delivery](references/delivery.md)。

需要了解各阶段怎样衔接或如何中途接续时，读[材料界面图示例](references/worked-example.md)。
