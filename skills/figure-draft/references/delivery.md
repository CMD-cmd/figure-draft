# 导出、图注与正文整合

只交付当前请求所需的阶段产物。常见成品包包括：原生 `.af`、保留真实文字的 SVG/PDF、按用途渲染的 PNG/TIFF、文字台账（`labels.json`）、图注，以及简短的来源与验收记录。按目标格式选择，不为凑齐文件包生成无用途产物。

先分辨子任务：只导出读第 1 节；只写图注读第 2 节；需要将图放回正文时才读第 3 节。已有可用图源直接接续，纯格式转换不补做科学立项、风格探索或 Affinity 重建。目标期刊未变且已有有效规格时直接复用；单纯按明确尺寸转格式不以重新检索投稿政策为前提。

## 1. 导出与结构检查

1. **确认目标规格**：继承用户或已核规范给出的最终物理尺寸、色彩空间、分辨率和文件格式。仅当投稿规格缺失或失效时补查目标期刊；不把单一期刊的数值当作通用标准。
2. **从主图源直接导出**：SVG/PDF 交付默认保留可编辑文本，转曲轮廓版另存。用户仅要求 PNG/TIFF 时直接从现有源渲染，不强制新增 PDF/SVG 或 `.af`。
3. **检查导出表现**：核对透明度、裁剪、渐变、线端与字体的实际导出效果。PDF 字体清单出现第二字体时，定位具体字形并判断是否为合理的符号 fallback。
4. **位图分辨率换算**：`像素宽度 = 最终物理宽度 (mm) ÷ 25.4 × DPI`。仅修改文件 DPI 元数据不会增加像素细节，须从原生矢量或高分辨源按目标尺寸重新渲染。
5. **运行纯矢量结构检查**：本次生成纯矢量 SVG/PDF 时，对实际导出文件运行 `audit_vector.py`；仅有 PDF 且无 SVG 时使用 PDF 检查能力，不为迎合脚本必填参数伪造 SVG；仅导出位图时检查像素、尺寸和视觉表现，不强制运行矢量脚本。
6. **最终尺寸视觉复核**：打开实际保存的导出文件，在最终刊印尺寸、全部面板及高风险局部（200–800%）下看图；请求包含原生稿时，一并完成保存重开验证。

### `audit_vector.py` 参数与状态说明

脚本调用格式：`--svg PATH [--pdf PATH] [--labels PATH] [--out PATH]`。SVG 检查仅用 Python 标准库；PDF 检查依赖 PyMuPDF。缺少依赖仅影响对应项，须如实记录缺口并在获准安装后重跑，不得把未审计写成通过。

| 状态 | 退出码 | 含义与后续动作 |
|---|---|---|
| `PASS` | `0` | 本次请求的检查项未发现明确结构问题；仍需结合实际看图确认视觉与科学质量 |
| `REVIEW` | `0` | 无硬性结构失败，但存在需人工复核的条目（如标签跨多个文本 run、上下标/电荷字形需肉眼核对）；必须逐项读取 `findings` 人工确认 |
| `FAIL` | `1` | 存在明确违反纯矢量契约的结构错误（如混入位图、缺失预期标签、非法外部引用）；修复后再交付 |
| `NOT_AUDITABLE` | `2` | 输入文件损坏、格式不受支持或缺少 PyMuPDF 等审计依赖；排障后重跑，不可计为通过 |

提供 `--labels` 时才按文字台账核对预期标签；未提供时报告提取到的文字。检查结果对应本次提供的文件和参数。

**渐变与位图的区分**：部分 PyMuPDF 版本的 `get_image_info()` 会把原生矢量渐变（shading）的临时渲染计入列表；脚本会同时核对图像绘制指令、资源字典与 Image XObject，保留合法的原生矢量渐变并识别真正的内嵌位图。不要单凭单一图像计数断定“含位图”或“无位图”。

**纯矢量与混合图的边界**：零嵌入位图只是纯矢量示意图的结构要求之一，本身不能证明原生对象可编辑性。包含真实显微图、实验照片或冻结数据面板的混合图，必须保留有真实来源的原始图像：可在单独导出的示意图层上运行纯矢量检查，整图则按混合图标准核对影像来源、分辨率与未篡改内容，不得因脚本对合法照片报 `FAIL` 而删改真实实验影像。

**多面板组版**：组装已完成的 R/Python 数据图、照片与示意面板时，保留各面板的来源、后端与版本记录。冻结数据面板的数据标记、坐标轴、图例编码和数值保持不变，仅做等比例放置，并在最终组版尺寸下检查字体大小、比例尺和可比面板对齐。若需修改数据标记或重绘坐标，必须回到原数据绘图后端生成后再替换。分面板检查与最终整图版面检查各做一次，不按每个 Skill 重复跑整套流程。

## 2. 图注按当前图重写

用户只要求写或改图注时，查看当前图稿及有关证据后直接撰写，不打开绘图软件或要求运行 Python/R。仅需参考期刊图注格式时，借用 `nature-figure` 的对应参考段落，不启动其绘图路线。

图注按**“图的主题 → 各面板内容 → 图中符号/线型/尺度解释 → 必要的来源、适用范围与声明”**顺序组织，并按目标期刊规定补全统计说明、缩写定义和 AI 使用披露：

- 图中的每个物相、箭头语义和局部放大图都能在图注或图例中准确定位。
- 图内已删除或合并的元素，同步清理图注中的旧说明。
- 条件性机制使用清楚的条件句，不把大段正文争论塞进图注。
- 参考文献对应原始研究与实际实验模型，不借示意标签夸大临床结论。
- 区分概念示意与真实观测：示意性的粒径、相区比例与器件分离距离在必要处说明。

初稿图注由本阶段直接完成；涉及正文论证结构重写时才接入 `nature-writing`。由正式审稿意见触发的图与图注改动，按需通过 `nature-response` 维护“审稿意见—改图—正文—回复信”的一致映射。

## 3. 放回正文

用户授权将配图整合回正文稿件后：

1. 基于实际主稿建立新版本副本，保留旧版文档与原图。
2. 替换对应图位，保持正确长宽比与出版清晰度。
3. 核对正文首次引图位置、面板编号、材料/生物学名、机制解释与图注完全一致。
4. 明确图与正文的信息分工，优先压缩正文中与图面重复的机械描述。
5. 保护 Word 中的 Zotero 域代码与交叉引用字段；渲染相关页面与整稿，检查分页与版式。
6. 分别记录 `native_figure_version`（图源版本）与 `manuscript_figure_version`（正文嵌入版本），确认实际替换完成后再同步状态。

注意：Word 文件包（`.docx` XML）的字段结构检查与桌面端 Zotero Refresh 是两项不同的验证，须按实际执行过的操作如实报告。

## 4. 交付表述

交付时先给出主文件和可预览图像，再简明列出本轮完成的关键改动、已验证项和仍影响使用的实质缺口。图内标签、图注与对外说明只呈现确认后的正向科学内容；过程纠错与弃稿原因留在内部工作记录中。

正式投稿候选需核对[期刊与来源](policy-and-provenance.md)；相同用途和目标期刊下直接复用仍有效的已核记录，临近实际投稿时再确认政策时效。原生矢量完成度、作者科学认可、期刊政策核查和实际投稿状态分别独立记录。
