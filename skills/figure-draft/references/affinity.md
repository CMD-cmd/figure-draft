# Affinity 原生矢量重建

适用于从草图/生成图重建，或精修已有 `.af`。使用可用 `affinity` Skill 的操作规则，已读且有效时复用；SDK按实际功能查询。新建/重建才执行下方场景拆解与完整编辑检验；已有文件改字只读取目标文字及其邻近区域，导出/只读检查也只执行对应部分。此路线允许有科学表达作用、可编辑的轻微渐变和矢量纹理。

## 1. 检查实际能力

优先发现 `execute_script`、`render_spread`、SDK 文档等 Affinity MCP 工具。工具缺失时查看现有 Affinity Skill 的连接方式与本机配置，先做只读检查。已有完整 Skill、服务与可用连接时复用，不重复安装。

若用户授权安装而确有缺项，使用已审查的可信来源安装最少所需组件；保留既有配置。权限拒绝按其原义处理；不得绕过应用允许的文件根目录。另一聊天/执行者正在使用 Affinity 时，不重启、不改共享设置、不关闭其文档。

新建原生稿的能力检查包括：应用/版本、文档读写、曲线/形状、填充/渐变、文字和字体、导出、保存重开。局部任务只补当前依赖的能力；复用同一连接已核得的preamble/SDK与会话记录，重连或API版本改变时再刷新。没有实际验证的能力标为待验证。

## 2. 保护文件与操作范围

读取当前打开文档的路径、`sessionUuid` 和 dirty 状态，匹配用户指向的版本。首次修改用户原件前创建新版本副本；已为本任务建立且已核对的工作副本可直接接续，只读/导出不要求另建工程。不要依赖 `Document.current` 长期指向同一个文档。保留来源图、之前的原生版本和导出。

操作 Vector 工作室；工作室只是界面状态，文件类型仍需由对象清单与实际编辑检验。应用仅允许 Desktop 时，在获准根目录创建任务工作副本，保存完成后用系统文件操作复制到项目并核对 hash。原生 API 的权限拒绝不能通过隐蔽路径或链接绕过。

共享应用同一时刻只由一个执行者操作。图稿已有另一个写入者时，先用冻结的导出/源代码作只读研究。

## 3. 从科学对象拆解场景

先建立对象树与层级，再绘制。推荐结构按实际内容调整：

```text
00 Background
01 Panel A
   Material / Tissue / Interface / Mechanism / Locator
02 Panel B
03 Panel C
04 Labels
05 Equations and legends
90 Reference (locked, hidden for export)
```

每个组按科学实体命名，重复部件用共享母形或参数生成，单个实体的轮廓由少量有意义的曲线构成。背景、插画、标签、方程分别可选、可隐藏和可编辑。

- 规则对象使用原生椭圆、矩形、圆角或布尔组合；有机物用闭合 Bézier 轮廓。
- 聚合物链用连续曲线及可控的描边层；断链通过真实路径分段表达，圆头/方头依据语义设置。
- 颗粒用有限的形状家族和有界大小差异；粗糙感用轮廓、局部矢量细节与克制填充表现。
- 骨/组织保持连通区域和明确边界；孔、腔与纹理依照科学含义布局。
- 金属可用方向统一的窄幅明暗变化、有限排线与稳定轮廓；保留腐蚀层与剩余金属的可读区分。
- 界面可以整体有方向、局部不规则；局部接触处真正接触，液相/孔隙保留应有的不连续性。

自动描摹只能作为定位草稿。密集像素轮廓、多边形拼片或大量小三角形即使导出为 SVG，也不满足用户要求的逐对象曲线重建。原图内文字不描成路径，不靠增加节点数量追求相似。

## 4. 图形与文字两条制作线

先完成形状、填充、层级与布局，按 `labels.json` 新建原生文字。文字线独立维护字体、字重、字号、基线、换行和上下标。

- 枚举实际安装字体与 PostScript 名称，选同家族的所需字重；检查导出后发生的 fallback。
- 保持文字对象的自然比例，缩放矩阵正常；通过字号和布局控制宽度，不水平拉伸字形。
- 化学式以真实字符和原生上下标属性构成；对比视觉字形与可提取语义文本。
- 常见拼写与排版错误按科学准确性修正，记录变更；术语含义不明时核证。
- 调整文字以后重查相邻引线和圆框；移动标签不能悄悄改变它所指的实体。

## 5. 原生构建方式

优先直接调用原生 `ShapeNodeDefinition`、`PolyCurveNodeDefinition` 和文字对象创建 API。也可先用确定性场景描述组织坐标/命令，再通过 SDK 创建相应对象。SVG 可作为交换格式，但须核对导入后仍是可操作的曲线与文字；放置一张嵌入图片不算完成重建。

每次执行一个逻辑步骤，记录目标文档、对象数量和变化；立即渲染并看实际结果。批量生成后先检查一个代表面板及重复部件，再扩展。

遇到 SDK/坐标/渐变/遮罩问题时读 [Affinity 实作要点](affinity-sdk-notes.md)，以当前 SDK 为准。不要重用历史 `sessionUuid`、绝对输出路径或“最后一个图层”假设。

## 6. 按改动范围检验编辑性

新建/重建或声称完整对象可编辑时，在任务副本进行以下可逆测试并恢复。已有文字对象的局部改字本身即可提供文字编辑证据，不额外改动无关曲线；只导出使用已有原生验收记录并检查此次导出，不为重做测试修改源文件。

1. 选一个标签改字，确认是独立原生文字；恢复。
2. 选一个主体修改填充或移动一个 Bézier 控制点，确认邻近实体和文字保持独立；恢复。
3. 隐藏文字层，确认插画中没有残留文字像素/字形；恢复。
4. 导出并保存，关闭/重开仅自己创建的已保存副本，重新核对对象与显示。
5. 在 400–800% 看曲线和连接，在最终物理尺寸看可读性。屏幕/PNG放大出现像素不单独证明源对象是位图，需同时查看对象类型及矢量导出。

对象数量只是证据的一部分。每个对象有合理边界、能做常用修改、层级可理解，才支持“对象级可编辑”。

## 7. 结构与视觉分别验收

交付纯矢量SVG/PDF时，运行本Skill的 `scripts/audit_vector.py` 并仅提供本次实际导出的文件；若请求仅为 `.af` 改字，不为运行脚本额外制造SVG/PDF。纯矢量图的SVG/PDF不应嵌入位图；混合真实图像的整图按影像来源验收，纯矢量脚本只适用于单独示意部分。

按 [review](review.md) 复查整图、面板和局部。原生可编辑、导出清晰、对参考的视觉忠实度分别写结果；“1∶1”需求中仍应列明实际差异，不能用文件扩展名或高节点数当作相似度验收。
