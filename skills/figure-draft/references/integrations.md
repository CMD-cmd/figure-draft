# 工具与技能接入

在首次执行生图、原生编辑或数据绘图，以及对应能力暂不可用时读取。先查看当前环境的工具目录、已安装技能和已有图源，再选择当前阶段所需的能力。

按宿主 Agent 实际提供的工具、MCP 或插件接入。下表中的技能名称用于定位可选能力；环境采用其他等效工具时，沿用相应的操作规范与授权范围。

## 1. 选择执行方式

| 当前任务 | 可用环境能力 | 接入方式 |
|---|---|---|
| 科学内容、布局或图注讨论 | 论文、实验记录、图稿与语言能力 | 直接使用本 Skill 对应模块；证据不足时补查原文 |
| 参考图检索与分析 | 浏览、文献检索、Zotero 或用户参考图 | 打开相应原图与图注，记录来源和可借鉴的视觉规则 |
| 示意位图生成/编辑 | 当前环境的图像生成工具 | 优先读取实际工具 schema；安装了 `imagegen` Skill 时按需读取其规范 |
| Affinity 原生绘制 | Affinity MCP 与应用 SDK | 已安装 `affinity` Skill 时复用其操作规则；否则读取 MCP preamble 与对应 SDK 文档，按本 Skill 的 [Affinity 模块](affinity.md)执行 |
| SVG 与参数图源 | 文件编辑、脚本及 SVG 渲染器 | 保留原图源格式；已安装 `paper-figure` 时仅借用所选图型的规则或模板 |
| 数据绘图 | Python/R 图源、运行环境及真实数据 | 已安装 `nature-figure` 时复用其定量规则与后端；否则按本 Skill 的[数据模块](data-figures.md)直接检查并绘制 |
| 正文整合、图注措辞与审稿回复 | 稿件编辑与写作规范 | 正文论证用 `nature-writing`，正式审稿回复用 `nature-response`，措辞可参考 `anti-defensive-writing` 与 `no-negative-echo`；按当前任务读取对应段落。未安装时沿用现有写作能力和本 Skill 的相应规则 |
| 独立复核 | 获准的独立执行者及实际图像查看能力 | 提供当前冻结图稿和科学简报，核实对方实际看到的文件与返回意见 |

## 2. 携带当前任务的信息

根据技能目录中实际存在的名称与路径定位辅助技能，只读取当前任务所需的章节。

调用辅助技能时，携带当前主文件、所处阶段、已确认的内容与风格、本轮修改范围及输出要求，完成后返回调用方的当前阶段。从 Figure-draft 进入时保持 `workflow_owner: figure-draft`；其他流程借用本 Skill 的模块时，保持原有流程负责人。

## 3. 缺少工具时

1. **先做不依赖缺失工具的部分**：如科学内容梳理、布局线框、文字台账（`labels.json`）、图注草拟或文献来源核对。
2. **明确说明缺口并按授权补齐**：需要实际生图、Affinity 原生操作、脚本渲染或 PDF 结构检查而环境缺少对应工具/依赖时，向用户说明具体缺失项，并在授权范围内连接或安装；同时继续使用已能正常工作的工具和任务工作副本。
3. **严格遵守外部模型与服务边界**：用户明确选择外部模型或特定 API 时，按当前聊天授权和对应工具规则提供材料；工具的实际名称、参数、可见模型标识与权限均以当前运行环境为准，不静默替换渠道或自动切换付费服务。
